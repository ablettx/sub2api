## 状态与使用方式

本矩阵对应已确认的[需求规格](specs/user-account-dynamic-quota/spec.md)、[技术设计](design.md)和[实现计划](tasks.md)。需求、技术设计、实现计划及 Live 边界已确认。已完成本地实现、核心链路测试和模拟升级/回退，下表记录实际证据及尚未执行的组合。文档结构、链接或 OpenSpec 校验通过不能替代代码、数据库、浏览器、发布或生产证据。

S01～S43 按需求规格中 Scenario 的顺序一一编号，不增加或改写原需求。V01～V26 覆盖设计及入口核验发现的风险，Live 排除受控账号的实现与调度测试已经完成。任务号对应 `tasks.md` 的实际编号；实现期间发现新入口或规则变动，应先同步规格、任务与矩阵。

验证层约定：单元验证金额和状态规则；仓储验证隔离数据库中的事务与竞争；接口验证真实 Handler、权限、调度及模拟上游；页面验证实际浏览器交互；升级验证隔离安装目录中的两个维护版本及持久数据。需要组合证据的条目不能只用一项单测代替。

- 复用项目现有测试设施和仓储 testcontainers：独立 PostgreSQL、Redis、假用户及 Key、模拟上游；不得使用生产连接串、生产账库或真实收费接口作为默认测试依赖。

- 统一准备 A/B/C/D、账号 X/Y、原分组 G1 和显式回退分组 G2。覆盖同用户多 Key、无权账号、失效订阅、未受控账号；模拟价格明确区分 `actual_cost` 与账号统计费用。
- 使用可控制的时钟与上游快照复现周三 15:00 重置、漂移、暂用到期及跨周期结算；不能为测试修改生产时间或生产额度。
- 并发用例通过同步点构造准入和扣费竞争，记录成功准入数与模拟上游调用数；不能仅依赖随机压测恰好没有超额。
- 本地升级使用两个具备本功能的维护版本、独立安装目录和同一份隔离持久数据；模拟 GitHub Release/资产下载，覆盖嵌入前端，不向真实 Release 上传测试制品。
- 真实付费初始化、远程工作流、发布、生产数据库操作、部署及重启均不在本地验证的默认授权内。环境缺失应记录精确阻塞和未覆盖项，不更换成未授权目标。
